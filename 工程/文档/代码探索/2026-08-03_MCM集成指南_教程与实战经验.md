# MCM (Mod Configuration Menu) 集成指南 — 面向 Bannerlord 模组开发者

> 整理日期：2026-08-03
> 适用版本：MCM v5（Aragas/Bannerlord.MBOptionScreen）
> 官方文档：https://mcm.bannerlord.aragas.org/
> NuGet 包：Bannerlord.MCM

对于模组（MOD）开发者来说，集成 MCM 可以让你无需自己编写繁琐的 Gauntlet UI 界面，就能轻松暴露各种可调参数（如倍率、开关、数值滑动条）给玩家。

MCM 的核心设计思想是**声明式配置**：通过 C# 的特性（Attributes）或属性订阅机制，直接将配置类与界面绑定。

---

## 一、 引入依赖 (Setup)

在 `.csproj` 中引用 MCM 的 NuGet 包。**务必保留 `IncludeAssets="compile"`**，这样你的 MOD 编译时只引用 API，不会把 MCM 的实现 DLL 强绑定进你的产物。

```xml
<ItemGroup>
  <PackageReference Include="Bannerlord.MCM" Version="5.0.0" IncludeAssets="compile" />
</ItemGroup>
```

⚠️ **经验提示**：推荐只引用 API 库（`Bannerlord.MCM`，即原 `Bannerlord.MBOptionScreen.API`），这样你的 MOD 编译时不会强绑定 MCM 的具体实现版本，版本兼容性更好。

### SubModule.xml 两种集成方式

**方式 A：把 MCM 内含进自己的 /bin 文件夹**（自包含，玩家不装独立 MCM 也能程序化读写配置，只是没有选项屏 UI）

```xml
<SubModules>
  <SubModule>
    <Name value="MCMv5" />
    <DLLName value="MCMv5.dll" />
    <SubModuleClassType value="MCM.MCMSubModule" />
    <Tags />
  </SubModule>
  <SubModule>
    <Name value="MCMv5 Basic Implementation" />
    <DLLName value="MCMv5.dll" />
    <SubModuleClassType value="MCM.Internal.MCMImplementationSubModule" />
    <Tags />
  </SubModule>
</SubModules>
```

**方式 B：直接依赖 NexusMods 独立 MCM Mod**（推荐，玩家需单独装 MCM，体验完整选项屏）

```xml
<DependedModules>
  <DependedModule Id="Bannerlord.MBOptionScreen" />
</DependedModules>
```

> 玩家侧前置：Harmony、ButterLib、UIExtenderEx、MCM 四件套（社区常称 "Big Four"）。

## 二、 定义配置类 (Configuration Class)

创建一个配置类，继承自 `AttributeGlobalSettings<T>`，用特性能定义菜单中的选项。

```csharp
using MCM.Abstractions.Attributes;
using MCM.Abstractions.Attributes.v2;
using MCM.Abstractions.Base.Global;

namespace MyAwesomeMod
{
    // 定义在 MCM 菜单中的全局唯一标识、显示名称以及分组类别
    public class MyModSettings : AttributeGlobalSettings<MyModSettings>
    {
        public override string Id => "MyAwesomeMod_v1";
        public override string DisplayName => "我的酷炫 MOD 设置";
        public override string FolderName => "MyAwesomeMod"; // 配置文件保存路径文件夹
        public override string FormatType => "json2"; // 配置文件存储格式

        // ------------------ 1. 布尔开关 ------------------
        [SettingPropertyBool("启用超强杀敌", HintText = "开启后增加角色伤害", Order = 0, RequireRestart = false)]
        [SettingPropertyGroup("基础设置")]
        public bool EnableSuperDamage { get; set; } = false;

        // ------------------ 2. 数值滑动条 (浮点数) ------------------
        [SettingPropertyFloatingInteger("伤害倍率", 1.0f, 10.0f, "0.0 倍",
            HintText = "调整玩家造成的额外伤害比例", Order = 1)]
        [SettingPropertyGroup("基础设置")]
        public float DamageMultiplier { get; set; } = 1.5f;

        // ------------------ 3. 下拉菜单 / 枚举 ------------------
        public enum DifficultyMode { Easy, Normal, Hard }

        [SettingPropertyDropdown("难度选择", HintText = "影响整体游戏节奏", Order = 2)]
        [SettingPropertyGroup("高级模式")]
        public DifficultyMode SelectedDifficulty { get; set; } = DifficultyMode.Normal;
    }
}
```

### ⚠️ MCMv5 关键坑点（来自官方文档）

- **`FormatType` 不能直接用 `none`**：MCMv5 默认 `FormatType = "none"`，必须重写 `Settings.FormatType`（如 `"json"`、`"xml"`、`"json2"`）设置才能真正落盘保存，否则改动不会持久化。
- **实例可用时机**：设置实例在 `OnSubModuleLoad` 之后才可用，**最早只能在 `OnBeforeInitialModuleScreenSetAsRoot` 及之后**使用 `MyModSettings.Instance`。在 `OnSubModuleLoad` 里直接访问 `Instance` 可能拿到 null。

```csharp
protected override void OnBeforeInitialModuleScreenSetAsRoot()
{
    base.OnBeforeInitialModuleScreenSetAsRoot();
    var _ = MyModSettings.Instance; // 此时可用
}
```

### 三种设置类型

MCM 支持三种作用域，按需求选择基类：

| 类型 | 基类 | 说明 |
|------|------|------|
| Global（全局） | `AttributeGlobalSettings<T>` | 跨角色、跨存档共享，最常见 |
| PerCampaign（每战役） | `AttributePerCampaignSettings<T>` | 同一战役的不同存档间共享 |
| PerSave（每存档） | `AttributePerSaveSettings<T>` | 存于存档文件内；移除 MCM 后存档仍可玩，但无 MCM 时一旦保存，设置将永久清除 |

## 三、 在代码中读取配置 (Usage)

在 SubModule 或 Harmony 补丁里，通过 `MyModSettings.Instance` 直接读玩家当前设置：

```csharp
using HarmonyLib;
using TaleWorlds.MountAndBlade;

namespace MyAwesomeMod
{
    [HarmonyPatch(typeof(Agent), "Hit")]
    public class DamagePatch
    {
        private static void Prefix(ref AttackInformation attackInformation)
        {
            var settings = MyModSettings.Instance;
            if (settings != null && settings.EnableSuperDamage)
            {
                // attackInformation.Damage *= settings.DamageMultiplier;
            }
        }
    }
}
```

## 四、 常用 Attribute 快速查阅表（MCMv5）

> v2 API 全部继承自 `BaseSettingPropertyAttribute`，通用参数：`Order`、`RequireRestart`、`HintText`。

| 特性 | 用途 | 核心参数示例 |
|------|------|--------------|
| `[SettingPropertyBool]` | 开关 (True/False) | `(DisplayName, Order, RequireRestart, HintText)`；额外 `IsToggle`（作为组开关） |
| `[SettingPropertyInteger]` | 整数滑动条 | `(DisplayName, MinValue, MaxValue, DisplayFormat, Order, ...)` |
| `[SettingPropertyFloatingInteger]` | 浮点滑动条 | `(DisplayName, MinValue, MaxValue, Format, Order, HintText)` |
| `[SettingPropertyText]` | 文本输入 | `(DisplayName, Order, HintText)` |
| `[SettingPropertyDropdown]` | 下拉选择 | `(DisplayName, Order, HintText)`；绑定 `Dropdown<T>` 或 enum |
| `[SettingPropertyButton]` | 按钮 | `(DisplayName, Content = "Press Me", Order, ...)`；绑定 `Action` 委托 |
| `[SettingPropertyGroup]` | 分组/折叠栏 | `("大类/子分类", GroupOrder = 1)`；用 `/` 做层级分组 |

### 格式字符串 (Format String)
仅 `Integer` 与 `FloatingInteger` 支持，使用 .NET 自定义数字格式串：
- `"0 Denars"` → 显示为 `150 Denars`
- `"#0%"` → 显示为百分比
- `"0.0 倍"` → 显示为 `1.5 倍`

### 下拉框 (Dropdown) 进阶
`Dropdown<T>` 的 `T` 可为 `string` 或自定义类（自定义类需重写 `ToString()`）。也可直接绑定 enum 自动生成选项。

```csharp
[SettingPropertyDropdown("选择单位", Order = 0)]
[SettingPropertyGroup("高级")]
public Dropdown<string> UnitSelection { get; set; } =
    new Dropdown<string>(new[] { "步兵", "骑兵", "弓箭手" }, 0);
```

### 按钮 (Button) 示例
```csharp
[SettingPropertyButton("重置设置", Content = "点此重置", Order = 10, HintText = "恢复默认")]
[SettingPropertyGroup("高级")]
public Action ResetButton { get; set; } = () => { /* 重置逻辑 */ };
```

### 组开关 (IsToggle)
把一个 Bool 设为组的开关（折叠栏的启用/禁用）：
```csharp
[SettingPropertyBool("启用高级功能", IsToggle = true, Order = 0)]
[SettingPropertyGroup("高级模式")]
public bool AdvancedEnabled { get; set; } = true;
```

## 五、 适配 MCM 软依赖 (Optional Dependency)

如果不希望 MCM 成为强制前置（未装 MCM 时 MOD 仍按默认参数运行），用 `try/catch` 解耦读取：

```csharp
public static class SettingsAdapter
{
    public static float GetDamageMultiplier()
    {
        try
        {
            return MyModSettings.Instance?.DamageMultiplier ?? 1.0f;
        }
        catch
        {
            return 1.0f; // 未安装 MCM 时返回默认值
        }
    }
}
```

> 此处的 `try/catch` 仅能保证 MOD 不崩，但玩家无法改设置（只能吃默认值）。
> **要让 MOD 在「有 MCM 时走 MCM 选项屏、没 MCM 时也能通过 XML 文件改设置」两种模式下都可用**，见第九章实战架构。

## 六、 多语言本地化 (Localization)

MCM 的设置显示名/提示文本默认就是你在 Attribute 里写的中文字符串，无需额外本地化文件即可中文显示。若需真正多语言（按游戏语言切换）：

1. **利用 Bannerlord 原生本地化机制**：在 MOD 的 `ModuleData/Localization` 下放 `xx.xml`（如 `zh.xml`、`en.xml`），用字符串 ID。
2. MCM 的 `DisplayName` / `HintText` 接受原生本地化 token（如 `{=abc123}伤害倍率`），MCM 会调用游戏本地化系统解析。
3. 推荐做法：把显示文本写成 `{=ID}默认文本` 形式，并在本地化 XML 中提供对应翻译，这样中/英玩家都能看到正确语言。

> 注：官方文档未提供 MCM 专用的本地化 Attribute，统一走 Bannerlord 的 Localization 系统。

## 七、 实战经验与常见坑（来自社区搜索整理）

1. **四件套顺序**：Harmony → ButterLib → UIExtenderEx → MCM，玩家加载顺序错会导致 MCM 不显示。
2. **`FormatType` 必须覆盖**：v5 默认 `none` 不落盘，记得写 `"json2"` / `"json"` / `"xml"`。
3. **`Instance` 时机**：只在 `OnBeforeInitialModuleScreenSetAsRoot` 之后访问，否则 null。
4. **`Id` 要全局唯一**：建议带版本号（如 `MyMod_v1`），改名/换版本后旧配置会被忽略。
5. **`RequireRestart`**：影响战斗数值的改动建议设 `RequireRestart = true`，避免热改导致状态不一致。
6. **配置保存位置**：全局/每战役配置在 `Documents/Mount and Blade II Bannerlord/Configs/<FolderName>/`；每存档配置在存档内部。
7. **软依赖读取**：用 `?.` 空传播 + `try/catch` 包住 `Instance` 访问，保证没装 MCM 也不崩。
8. **分组层级**：`[SettingPropertyGroup("战斗/伤害")]` 用 `/` 自动生成二级折叠栏，`GroupOrder` 控制组间顺序。

## 九、 双模式架构：有 MCM 走 MCM、没 MCM 走 XML（实战范例）

> 范例来源：`ProjectileTrajectorySystem` 模组（已实装该方案）。
> 目标：玩家装了 MCM → 在选项屏里调参；没装 MCM → 仍可手动改 `ProjectileTrajectorySettings.xml` 调参。两种情况下业务代码读取方式完全一致。

### 9.1 核心思想：单源数据 + 双后端

不要让业务代码直接依赖 `MCM.Instance`。而是拆成三层：

```
业务代码 ──读──> SettingsManager.Settings（纯数据，零 MCM 依赖）
                        │
          ┌─────────────┴─────────────┐
    有 MCM 后端                      无 MCM 后端
    ProjectileTrajectorySettings      ProjectileTrajectorySettingsData
    (继承 AttributeGlobalSettings)    + XML 文件读写
    MCM 负责读写/落盘                  SettingsManager 负责读写/落盘
```

- **`ProjectileTrajectorySettingsData`**：纯数据类（无 MCM 引用），所有 bool/int/float 字段 + 默认值。业务代码只认它。
- **`ProjectileTrajectorySettings`**：MCM 包装类，继承 `AttributeGlobalSettings<ProjectileTrajectorySettings>`，用 Attribute 装饰并把字段转发给 MCM UI（get/set 委托到 Data 或自身存值）。
- **`ProjectileTrajectorySettingsManager`**：统一入口，持有 `Settings` 引用；在 `OnSubModuleLoad` 阶段**反射探测 MCM 是否加载**，决定用哪个后端。

### 9.2 探测 MCM 是否存在的反射写法

关键在于不 `using MCM`（否则编译强绑定），而是用 `Type.GetType` 探测：

```csharp
// SettingsManager 中（无 using MCM.*）
private static bool CheckMcmAvailable()
{
    try
    {
        // 只探测类型是否存在，不真正引用类型 → 编译期不依赖 MCM 实现
        var mcmSettingsType = Type.GetType(
            "MCM.Abstractions.Base.Global.AttributeGlobalSettings`1, Bannerlord.MBOptionScreen");
        return mcmSettingsType != null;
    }
    catch
    {
        return false;
    }
}
```

> 因为 `.csproj` 只 `IncludeAssets="compile"`（见第一章），MCM 类型在运行时不一定存在。反射探测既能在装了 MCM 时启用选项屏，又能在没装时安全回落到 XML。

### 9.3 SettingsManager 初始化逻辑（核心）

```csharp
public static class ProjectileTrajectorySettingsManager
{
    public static ProjectileTrajectorySettingsBase Settings { get; private set; }

    public static void Initialize()
    {
        if (CheckMcmAvailable())
        {
            // 后端 A：MCM 接管读写与落盘
            Settings = ProjectileTrajectorySettings.Instance;
        }
        else
        {
            // 后端 B：自行从 XML 加载/保存
            Settings = ProjectileTrajectorySettingsData.Load();
        }
    }

    public static void Save()
    {
        if (Settings is ProjectileTrajectorySettingsData data)
            data.Save();          // 写回 ProjectileTrajectorySettings.xml
        // MCM 后端由 MCM 自己落盘，无需手动 Save
    }
}
```

### 9.4 无 MCM 时的 XML 后端实现

`ProjectileTrajectorySettingsData` 用 Bannerlord 自带的 `ParseOptions` / `FileWriter` 读写 XML：

```csharp
// 读取（OnSubModuleLoad 时）
var path = Path.Combine(Utilities.GetConfigsPath(), "ProjectileTrajectorySystem",
                        "ProjectileTrajectorySettings.xml");
if (File.Exists(path))
{
    var doc = new XmlDocument();
    doc.Load(path);
    // 节点名与属性一一对应，缺失则用默认值
}

// 保存
using (var writer = new XmlWriter(path))
{
    writer.WriteStartElement("ProjectileTrajectorySettings");
    writer.WriteAttribute("EnableTrajectory", EnableTrajectory.ToString());
    // ...其余字段
    writer.WriteEndElement();
}
```

> 对应玩家可见的 `ProjectileTrajectorySettings.xml` 示例（节选）：
> ```xml
> <ProjectileTrajectorySettings>
>   <EnableTrajectory>true</EnableTrajectory>
>   <PlayerTrajectory>true</PlayerTrajectory>
>   <SlowMoTimeScale>0.35</SlowMoTimeScale>
> </ProjectileTrajectorySettings>
> ```

### 9.5 业务代码读取（与后端无关）

业务代码**永远只写一行**，根本不在乎当前是哪个后端：

```csharp
// 任何系统/补丁里
if (ProjectileTrajectorySettingsManager.Settings.EnableTrajectory)
{
    // 渲染弹道...
}
```

这正是双模式的价值：**增加一层 Manager 转发，业务代码零改动即可在两种模式下工作。**

### 9.6 SubModule.xml 配合

因为走软依赖 + 反射探测，**不要在 `SubModule.xml` 里写 `<DependedModule Id="Bannerlord.MBOptionScreen" />`**。这样没装 MCM 时 MOD 也能正常加载并走 XML 后端。

```xml
<!-- 不写 DependedModule；若想更稳妥也可显式声明可选 -->
<!-- 可选：声明 MCM 为可选依赖，提升加载兼容性 -->
<OptionalDependedModules>
  <OptionalDependedModule Id="Bannerlord.MBOptionScreen" />
</OptionalDependedModules>
```

### 9.7 该架构的优点与注意点

| 优点 | 注意点 |
|------|--------|
| 玩家零前置（不装 MCM 也能玩、能调参） | XML 字段改名需做兼容读取（旧档缺字段用默认值） |
| 装 MCM 自动获得图形选项屏 | MCM 后端改动由 MCM 落盘；XML 后端要自己 Save |
| 业务代码完全解耦 MCM | 反射探测的 type 字符串要与 MCM 实际命名空间一致 |
| 一份数据定义，两种呈现 | MCM 包装类与 Data 类字段要手工保持同步 |
