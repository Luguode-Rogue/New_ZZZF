# 坐骑性能属性参考

记录日期：2026-10-01。依据：Bannerlord 1.5.0 托管源码。

工程源码：`Modules/New_ZZZF/工程/New_ZZZF`；Mod 根目录：`Modules/New_ZZZF`。
以下区分实际调用链与字段名称，不能把中文直译作为引擎效果的证明。

## 属性表

| 属性 | 属性名中文直译 | 源码中的实际作用 | 修改注意事项 |
|---|---|---|---|
| `MountSpeed` | 坐骑速度 | 原版根据马匹速度、骑术、装备、旗帜和环境计算，写入坐骑运动速度参数。 | 改变速度参数，不直接设置当前速度，也不会同时修改加速参数。 |
| `MountManeuver` | 坐骑机动性 | 装备操控值叠加骑术和技能等修正后，提交给坐骑引擎。 | 1.3倍参数不代表转向角速度必然增加30%；底层换算尚未确认。 |
| `MountDashAccelerationMultiplier` | 坐骑疾驰加速度倍率 | 原版根据马匹、马具重量计算；重装备降低倍率，湿地另乘0.75。 | 独立的加速调节入口；只改速度和操控不会自动改变它。底层作用曲线未确认。 |
| `TopSpeedReachDuration` | 达到最高速度所需时长 | 坐骑分支实际写入 `RidingModel.CalculateAcceleration()` 的返回值。骑术、装备操控提高通常使返回值增大。 | 坐骑上不能凭名称认定为秒数，也不能照搬步兵的除法规则；增减对实测加速的方向待验证。 |
| `MountChargeDamage` | 坐骑冲撞伤害 | 直接乘入马匹撞人的基础威力计算。 | 可以独立增强冲撞；最终伤害仍受后续伤害结算影响。 |
| `ArmorTorso` | 躯干护甲 | 坐骑分支汇总装备护甲，再应用骑术技能等修正。 | 修改坐骑承伤属性，不会给骑手增加护甲。 |
| `HealthLimit` | 生命值上限 | 控制坐骑最大生命，是 Agent 的生命属性。 | 提高上限不等于同步恢复当前生命。 |
| `Health` | 生命值 | 控制坐骑当前生命，是 Agent 的生命属性。 | 与运动性能参数独立；单纯属性重算不等于回血。 |
| `AttributeRiding` | 骑术属性 | 骑手的值为有效骑术乘坐骑系数；坐骑有马具时系数为1，无马具时为0.8。 | 改最终字段不会重新计算通过 `GetEffectiveSkill(Riding)` 取值的速度、操控、加速公式。 |
| `MountDifficulty` | 坐骑难度 | `Agent.CanRide` 比较骑手有效骑术与此参数，判定能否骑乘。 | 属于骑乘门槛，不能当作速度或操控增益。 |

## 属性提交链

`Agent.UpdateAgentProperties()` → `AgentDrivenProperties.UpdateDrivenProperties(agent)` →
`AgentStatCalculateModel.UpdateAgentStats(agent, properties)` →
`MBAPI.IMBAgent.UpdateDrivenProperties(agentPointer, values)`。

坐骑分支使用坐骑 Agent 的属性，骑手和坐骑是两个 Agent。Mod 的 Buff 可挂在骑手身上，但运动属性应在坐骑分支根据 `RiderAgent` 的 Buff 修改。
原版模型每次重算会重新生成基础值，Buff 应在 `base.UpdateAgentStats` 之后应用，避免覆盖或逐次累乘。

## 加速计算：不能只看名称

`DefaultRidingModel.CalculateAcceleration`：

```text
a = 装备修正后的马匹操控值 × 0.008
若骑术 >= 0：
    a *= 0.7 + 0.003 × (骑术 - 1.5 × 骑乘难度)
返回 clamp(a, 0.15, 0.7)
```

坐骑属性计算把该结果写入 `TopSpeedReachDuration`。
这里读取装备操控值，不读取最终 `MountManeuver`。所以在模型末尾把 `MountManeuver` 乘1.3，不会让上述加速公式自动重算。
步兵的同名属性采用另一套计算，不能将步兵与坐骑的倍率方向混为一谈。

疾驰加速倍率使用重量项：

```text
w = 马匹重量 / 2 + 马具重量
w <= 200：倍率 = 1
200 < w < 300：倍率 = 1 - (w - 200) / 111
w >= 300：倍率 = 0.1
湿地：倍率 *= 0.75
```

## 冲撞计算

`ComputeBlowMagnitudeFromHorseCharge` 中，有效相对速度包含目标速度在马匹运动方向上的投影及碰撞方向修正。
核心表达式是：`基础威力 = 有效相对速度² × 碰撞方向系数 × MountChargeDamage`。
因此增速可能明显放大冲撞威力，不能把它只视作位移速度调整。

## 其他限制与验证边界

- `SetMaximumSpeedLimit` 是独立的限速接口；原版编队更新会同时设置骑手和坐骑的限速。
- 更高速度参数不保证 NPC 持续全速行进；输入、编队限速、碰撞及环境仍影响实际运动。
- `WalkingSpeedLimitOfMountable` 和 `GetTurnSpeed()` 是原生引擎读取接口，不是已找到的可直接赋值属性。
- 当前托管属性枚举没有独立的坐骑刹车倍率。不能仅凭 `MountManeuver` 推断刹车提升比例。
- 本地源码不含相关 C++ 运动实现。速度参数的最终换算、转向曲线、加速参数的精确方向和倍率仍需单项游戏测试。

## 当前设置与外部研究（2026-10-01）

英雄祝福的坐骑 `MountSpeed`、`MountManeuver`、`MountDashAccelerationMultiplier`、`TopSpeedReachDuration` 参数均恢复为 ×1.3，移除极端测试数值。最后一项在坐骑上的运动效果尚未确认，不能把参数增幅等同于已验证的加速增幅。

此前 TopSpeedReachDuration 的乘、除测试，玩家未观察到明显加速效果；疾驰加速倍率的极端测试也未达到预期。

Better Horses 在 SandboxAgentStatCalculateModel.UpdateAgentStats 的后置补丁中，对坐骑 Agent 的 MountSpeed、MountManeuver、MountDashAccelerationMultiplier、MountChargeDamage 分别乘配置倍率，未使用 TopSpeedReachDuration。

其配置允许速度、加速倍率0～100，操控倍率0～4。这些是 Mod 配置范围，不是已证明的引擎上限；该旧 Mod 的实现也不能保证与当前游戏版本完全一致。
配置：https://github.com/Shadow32055/Bannerlord.BetterHorses/blob/main/BetterHorses/Settings/MCMSettings.cs

### 关于最大限制

- 已确认：原版 CalculateAcceleration 返回值 clamp 在0.15～0.7；这是基础模型计算阶段的限制。
- Buff 在基础模型之后乘倍率，托管 SetStat 只写入数组，没有发现它在此处重新钳制到0.7。
- MountDashAccelerationMultiplier 通常由装备重量生成0.1～1之间的值，并可被湿地进一步降低。这个基础生成范围不能当作所有后续写入的硬上限。
- 编队通过 SetMaximumSpeedLimit 另行限制骑手和坐骑，速度参数增加仍可能受当前限速影响。
- 没有找到可信的原生引擎代码或实测证据，证明上述加速字段存在固定最大倍率；也不能排除底层非线性、饱和或特定步态限制。
- GetAgentDrivenPropertyValue 读取托管数组，不能据此证明实际运动已应用倍率。
