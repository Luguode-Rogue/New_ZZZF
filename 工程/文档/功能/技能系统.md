## 2. 当前设计原则

技能系统应分为数据定义、运行时效果、触发/调度、UI 展示、持久化与兼容层。UI 不应成为技能运行时逻辑的唯一数据源。

## 3. 新技能开发标准流程

1. 明确技能类型与目标载体。
2. 确认事件触发点和持续生命周期。
3. 定义数据与配置来源。
4. 实现运行时效果。
5. 接入 UI / Tooltip / 本地化。
6. 完成存档读档路径。
7. 进行战场、地图、切换场景和重复初始化测试。
8. 把遇到的失败方案与修复根因登记到 Bug 经验库。

## 4. UI 与 HtmlUI

CustomSkill HtmlUI 重制属于表现层改造，不应复制一套独立技能逻辑。技能数据应通过稳定接口提供给 UI，避免 HTML 直接依赖 Bannerlord 内部对象生命周期。

## 5. API 兼容

API 版本差异、缺少字段/方法、类型迁移等问题不要散落在具体技能文档中。统一参考 `API迁移记忆库.md`，并在发现新版本差异时补充验证条件和替代方案。

## 6. 示例

个人 Buff、光环 Buff、士兵技能等示例保留在原目录，后续可以进一步建立 `示例/技能系统_示例.md` 作为统一索引，但不删除原始示例文件。

## 7. 历史排错要求

技能系统曾出现存档读档丢失、UI 裁剪、点击穿透/跳转、地图暂停、API 迁移等问题。它们全部属于长期知识，不得在整理时只留下最终结论而删除排查过程。

详见 [Bug 修复经验库](../历史/BUG_HISTORY.md)。
