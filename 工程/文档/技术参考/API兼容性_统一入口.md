# Bannerlord API 兼容性统一入口

本页是跨功能 API 兼容问题的统一导航。原始 `API迁移记忆库.md`、代码探索和 Bug 记录继续保留完整内容。

## 什么时候先看这里

- `MissingMethodException`
- `MissingFieldException`
- 同一功能在不同 Bannerlord 版本行为不同
- TaleWorlds 私有字段/属性/方法改变
- GauntletUI / UIExtenderEx / MCM API 改名或类型变化
- 反射成功但运行时行为异常

## 必须记录的兼容信息

每个新兼容问题至少记录：

```text
Bannerlord 版本：
API / DLL：
异常类型：
异常成员：
触发位置：
原实现：
失败原因：
替代实现：
Fallback：
已验证版本：
未验证版本：
```

## 推荐排查顺序

1. 确认实际运行游戏版本和加载 DLL。
2. 确认异常是缺方法、缺字段、类型变化还是行为变化。
3. 查原始 API 迁移记忆库。
4. 查 Bug 经验库是否已经出现同类问题。
5. 将版本敏感代码隔离到 Compatibility 层，避免散落在业务逻辑中。
6. 验证 fallback，而不是只验证当前版本。

## 重要原则

不要用“当前版本能编译”替代“兼容性已经验证”。

不要为解决单个 API 编译问题随意改变整个项目的目标版本或语言版本。

版本敏感实现必须同时保留失败版本、原因、替代方案和验证结果，避免未来重复逆向。
