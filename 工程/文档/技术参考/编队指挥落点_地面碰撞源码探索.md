## 二、获取"地面碰撞点"的两种官方做法

### 1. 由相机 + 鼠标位置直接求地面点（最省事）

`MissionScreen.GetProjectedMousePositionOnGround(ref Vec3 result, bool avoidBehindCamera)`：

```csharp
// MissionScreen.cs
public WorldPosition GetProjectedMousePositionOnGround(int extraHeight = 0, bool avoidBehindCamera = false)
{
    ...
    WorldPosition result = new WorldPosition(Mission.Current.Scene, this.SceneView.ProjectedMousePositionOnGround(extraHeight, avoidBehindCamera));
    return result;
}
```

底层 `SceneView.ProjectedMousePositionOnGround` 由原生引擎实现：从当前相机经鼠标屏幕位置发射一条射线，
求与**地形 / 实体**的交点。这正是"棋子贴地"用的官方入口。

### 2. 纯托管自管射线（OrderTroopPlacer 的等价实现，更适合自定义弹道）

`OrderTroopPlacer.TryGetScreenMiddleToWorldPosition()` 用纯托管逻辑发射射线求地面交，
与我们弹道落点的做法非常类似：

```csharp
// OrderTroopPlacer.cs ~L527
bool didHit = this.Mission.Scene.RayCastForClosestEntityOrTerrain(
    rayOrigin, rayTarget, out float hitDistance, out Vec3 hitPoint, out GameEntity _, 0.1f);
if (didHit)
{
    hitPoint = GetValidGroundPosition(hitPoint);
}
```

**关键：官方对"落点"有一个统一的地面合法性处理辅助**，这正是我们要借鉴的——避免 NaN / 悬空 / 穿地：

```csharp
// OrderTroopPlacer.cs ~L575
public static Vec3 GetValidGroundPosition(Vec3 position)
{
    position.Z = position.Z + 0.2f;                        // 略微抬高，避免嵌进地面
    position.Z = (position.Z < 0f) ? 0f : position.Z;      // 保底不低于 0
    position.Z = (position.Z > 40f) ? 40f : position.Z;    // 上限钳制
    WorldPosition worldPosition = new WorldPosition(this.Mission.Scene, position);
    worldPosition.GetGroundVec3();                         // 吸附到真实地形高度
    return worldPosition.GetVec3();
}
```

`WorldPosition.GetGroundVec3()` 是引擎原生方法：把任意 (x, y, z) 重新吸附到地形表面高度，
比自己欧拉积分逐段 RayCast 更稳，且自带地面合法性校验。

## 三、对我们"攻城武器自动追落点视角"的启示

当前 `PlayerTrajectorySystem.ComputeSiegeLandingPoint` 用欧拉积分 + 逐段
`RayCastForClosestEntityOrTerrain` 模拟弹道找落点，存在 NaN / 方向零向量 / 高低地形穿模风险。

官方的稳妥做法是：
1. 先用弹道求出大致命中点的 **(x, y)**；
2. 再用 `WorldPosition.GetGroundVec3()` 把它吸附到真实地形高度。

优点：
- 不用纠结命中瞬间 z 的精度；
- 自动避开 NaN（零向量归一化产生的 NaN 不会贯入相机矩阵）；
- 落点一定贴地（原版棋子就是这么干的）。

### 推荐改造方向

- 弹道积分仍用于求 (x, y) 命中点（命中即停）；
- 命中后调用 `GetValidGroundPosition(hitPoint)`（或 `WorldPosition.GetGroundVec3()`）贴地；
- 在进入 `BuildViewFrame` / `SetLandingPoint` 前统一用 `IsFinite` 校验。

## 五、踩坑记录：`WorldPosition` 的取值 API（重要）

**文件**：`TaleWorlds.Engine/WorldPosition.cs`（注意命名空间是 `TaleWorlds.Engine`，不是 `TaleWorlds.Core`）

### 常见误用（编译报错 CS1061）

| 错误写法 | 原因 |
| --- | --- |
| `wp.GetVec3()` | `WorldPosition` **没有** `GetVec3()` 方法 |
| `wp.Position` | `WorldPosition` **没有** `Position` 属性 |

### 正确取值方式

`GetGroundVec3()` 是**有返回值的实例方法**，直接接收返回值即可：

```csharp
// TaleWorlds.Engine/WorldPosition.cs:203
public Vec3 GetGroundVec3()
{
    return new Vec3(this._position.AsVec2, this.GetGroundZ(), -1f);
}
```

**正确用法**：
```csharp
WorldPosition wp = new WorldPosition(Mission.Current.Scene, point);
Vec3 snapped = wp.GetGroundVec3();   // ← 直接接收返回值，不要写 wp.Position / wp.GetVec3()
```

### 其他可用取值成员（按需）

| 成员 | 返回 | 说明 |
| --- | --- | --- |
| `GetGroundVec3()` | `Vec3` | 吸附地形高度后的点（最常用） |
| `GetGroundZ()` | `float` | 仅地形 z（State < Valid 时返回 NaN） |
| `GetNavMeshVec3()` | `Vec3` | 吸附导航网格高度后的点 |
| `GetVec3WithoutValidity()` | `Vec3` | 原始 _position，不做任何有效性校验 |
| `AsVec2` | `Vec2` | 仅 x,y |
| `X` / `Y` | `float` | 分量只读属性 |
| `IsValid` | `bool` | `AsVec2.IsValid && _scene != Zero` |

### 构造方式

```csharp
public WorldPosition(Scene scene, Vec3 position)   // 最常用
public WorldPosition(Scene scene, UIntPtr navMesh, Vec3 position, bool hasValidZ)
```

### 在 ProjectileTrajectorySystem 中的落地写法（仅通过静态编译/lint，游戏内未验证）

```csharp
private static Vec3 SnapToGround(Vec3 point)
{
    try
    {
        Vec3 p = point;
        p.z = p.z + 0.2f;
        p.z = Math.Max(p.z, 0f);
        p.z = Math.Min(p.z, 40f);
        WorldPosition wp = new WorldPosition(Mission.Current.Scene, p);
        Vec3 snapped = wp.GetGroundVec3();          // 正确：接收返回值
        if (wp.IsValid && !IsNonFinite(snapped.x) && !IsNonFinite(snapped.y) && !IsNonFinite(snapped.z))
            return snapped;
    }
    catch (Exception ex) { Debug.Print($"[SiegeLanding] SnapToGround failed: {ex.Message}"); }
    return point;
}
```

## 六、从源码找到的官方落地/地面碰撞方案（待游戏验证）

> **状态：以下是从骑砍2源码（RangedSiegeWeapon.cs / OrderTroopPlacer.cs）提取的真实官方做法。代码改动仅通过静态编译/lint，未进游戏实跑验证。**

### 引擎实际怎么判断"弹道是否撞到地面/障碍"

源码 `RangedSiegeWeapon.CanShootPointBallistic`（约 L1979-2001）与 `CanShootAtPoint` 系列，判断"从发射点到目标点之间有没有遮挡"用的是**射线检测，不是逐点比高度**：

```csharp
// 引擎片段（简化）
float t = shootingSpeed * MathF.Sin(verticalAngle) / 9.806f;   // 飞行时间
float peak = 4.903f * t * t;                                    // 抛物线顶点抬升量
Vec3 mid = (startGlobalPos + targetGlobalPos) / 2f + new Vec3(0f, 0f, peak); // 弹道中点抬高
this.Mission.Scene.RayCastForClosestEntityOrTerrainIgnoreEntity(
    startGlobalPos, mid,
    base.GameEntity.Root,                  // 忽略武器自身
    out float hitDist,
    out GameEntity hitEntity,
    this._projectileRadiusCached,          // 射线厚度 = 炮弹半径
    BodyFlags.CommonCollisionExcludeFlagsForMissile); // 排除弹体类 body
```

要点（与之前自创方案的关键差异）：
1. **API 是 `RayCastForClosestEntityOrTerrainIgnoreEntity`，不是 `RayCastForClosestEntityOrTerrain`**——前者能忽略自身实体，避免射线起点在炮体内时打到自己；
2. **射线厚度用 `_projectileRadiusCached`（炮弹半径）**，不是写死的 0.1f；
3. **带 `BodyFlags.CommonCollisionExcludeFlagsForMissile` 排除标志**，避免命中其他导弹类 body；
4. **引擎是"给定目标点→打射线验证可达"，而非"逐点比较 GetGroundZ"**。对"求落点"而言，等价做法是：沿弹道逐段，对每段 (pos→next) 打上述射线，命中即落点。

### 参数来源（官方做法，见 RangedSiegeWeapon L1321-1358 / L1802）

- **发射起点**：`MissileStartingPositionEntityForSimulation.GlobalPosition`（节点名 `projectile_leaving_position`，回退到 `Projectile` 某节点）。本模组 `SiegeWeaponHelper.GetProjectileStartPosition` 已取该节点，对齐。
- **初速方向/速度**：引擎发射时 `velocity = orientation.f * ShootingSpeed + globalVelocity`（L1802）。其中 `orientation.f` 是带仰角的发射朝向，`ShootingDirection` 属性 = `Projectile.GameEntity.GetGlobalFrame().rotation.u`（炮弹 node 的 up 轴）。本模组 `GetShootingDirection` 取的就是这个；但注意**没加 `globalVelocity`（攻城武器通常为 0）**，方向基本对等。
- **空气阻力**：`ItemObject.GetAirFrictionConstant(weaponClass, weaponFlags)`。本模组 `GetSiegeAirFriction` 用 `ItemObject.GetAirFrictionConstant` 近似。

### 本模组已改成的落地判定（对齐弹道显示，待游戏验证）

> 实测发现：原"射线方案"`RayCastForClosestEntityOrTerrainIgnoreEntity` 在攻城武器场景下**全程 miss**（日志实证 4000 步/40s 飞到 z=913 仍不命中），落点算不出 → 返回 Invalid/NaN。更糟的是 `SetLandingPoint` 用 `point != Vec3.Invalid && IsFinite(point)` 判断有效性，而 `NaN != Vec3.Invalid` 恒为 true，导致 NaN 误判为有效、相机乱飞——这就是"摄像机飞到的地方完全不是实际落点"的直接原因（弹道显示本身是对的，因为它只用 `CalculatePosition` 画线、不依赖碰撞判定）。
>
> 用户已明确："游戏内弹道显示和实际弹道落点重合"。因此**落点计算必须与弹道显示用完全同一套积分参数**，才能和显示重合。

`PlayerTrajectorySystem.ComputeSiegeLandingPoint`（新版）：
- 复用与 `SimulateAndRender` 完全相同的 `TrajectoryPhysics.CalculatePosition(startPos, dir, speed, t, airFriction)`；
- 积分区间与步长与弹道显示一致：`t` 从 0.3 到 4.8、步长 0.15；
- 对每步弹道点 `currentPos`，用 `Scene.GetTerrainHeight(new Vec2(currentPos.x, currentPos.y), true)` 取该 (x,y) 处真实地形高度 `groundZ`；
- 当 `currentPos.z <= groundZ + 0.3f` 时判定触地，落点返回 `(currentPos.x, currentPos.y, groundZ + 0.3f)`（z 吸附到地面，保证与显示/实际落点重合）；
- 全程严格 `IsFinite` 检查，任何 NaN/Inf 立即返回 `Vec3.Invalid`。

`SiegeLandingCameraSystem.SetLandingPoint`（已修）：
- 有效性判定改为**只依赖 `IsFinite(point)`**，不再用 `point != Vec3.Invalid`（`Vec3.Invalid` 在 NaN 面前不可靠），彻底屏蔽 NaN 落点被喂给相机。

> 新增的 `SiegeWeaponHelper.GetRootEntity` / `GetProjectileRadius` 现不再被落点计算使用（保留无妨）。

### 验证方法（需用户实跑）

进游戏操作攻城武器，看 `SiegeLanding.log`：
- 出现 `[Compute] LAND at t=... groundZ=... -> landing=...` 且落点贴合弹道显示末端 → 方案对；
- 仍 `[Compute] no land within t=[0.3,4.8]` → 弹道在 4.8s 内没落地，需调大 `timeEnd`（例如 8.0）或检查 `airFriction` 是否偏小导致弹道过高；
- 落点和显示仍偏差 → 检查 `GetTerrainHeight` 在该 (x,y) 是否返回正确地形 z（日志已打印 groundZ）。
