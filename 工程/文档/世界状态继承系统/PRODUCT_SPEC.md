# 产品需求规格说明书 (PRD)

## 1. 产品概述

**世界状态继承系统**（代号 LegacyWorld）是 New_ZZZF Mod 的子系统，允许玩家在 Bannerlord 多个 Campaign 存档之间传递世界政治状态。玩家可以在一个存档中导出当前世界状态为"世界遗产档案"，在下一局新游戏开始时自动继承该档案，使新世界成为旧世界的"平行历史"。

## 2. 用户故事

### 2.1 核心流程

> 作为一位 Bannerlord 玩家，我希望结束一局游戏后，下一局新游戏的卡拉迪亚大陆继承上一局的政治格局（王国边界、家族关系、领地归属等），而不是完全随机生成。

### 2.2 具体场景

| ID | 场景 | 优先级 |
|----|------|--------|
| US-01 | 玩家保存游戏时，自动导出当前世界状态到 JSON 文件 | P0 |
| US-02 | 玩家开始新游戏时，自动从 JSON 文件导入世界状态 | P0 |
| US-03 | 玩家通过 MCM 开关控制系统是否启用 | P0 |
| US-04 | 玩家可以选择恢复哪些类别（王国/家族/领地/经济） | P1 |

| US-06 | 玩家可以在 MCM 面板中手动触发导入（忽略同世界检测） | P1 |
| US-07 | 系统通过调试日志记录操作过程 | P1 |
| US-08 | 同一局游戏只导入一次，防止重复覆盖 | P1 |

## 3. 功能列表

### 3.1 导出系统 (Export Engine)

- **触发方式**：
  - 自动：文件保存时（`OnBeforeSaveEvent`）
  - 手动：MCM 按钮«手动导出»
- **导出内容**：所有王国、家族、定居点的当前状态（写 `Legacy.json`）；玩家人物模板累积写 `LegacyHeroes.json`
- **输出格式**：JSON（世界状态 `Legacy.json` 覆盖写；玩家人物 `LegacyHeroes.json` 累积写）
- **存储位置**：模块根目录（与 `SubModule.xml` 同级）

### 3.2 导入系统 (Import Engine)

- **触发方式**：
  - 自动：仅新游戏创建时（`OnNewGameCreatedEvent`），载入存档不触发
  - 手动：MCM 按钮«手动应用»（跳过同世界检测）
- **恢复顺序**：Kingdom → Clan → Settlement（依赖有序）
- **本存档保护**：player/companion 模板仅当当前 WorldId == 遗产 WorldId 且命中存活的自己/队友时跳过，禁止本存档二重身
- **防重复（持久化）**：已复刻的遗产世界记录于 `LegacyHeroes.json` 的 `applied_world_ids`，重开游戏也不重复复刻

### 3.3 MCM 设置面板

参见 [README.md](README.md#配置mcm-设置菜单) 或代码 `LegacyWorldMCMSettings.cs`。

### 3.4 调试日志

- 文件位置：`Modules\New_ZZZF\affix_debug.log`
- 日志标签：`BEHAVIOR`、`SERVICE`、`KINGDOMIMP`、`CLANIMP`、`SETTLEIMPORT`、`HERO`、`VERIFY`
- 运行时开关：MCM «启用调试日志»

### 3.5 英雄模板复刻 (Hero Resurrection)

- **状态**：已实现（v0.5.0 复刻 + v0.6.0 独立文件与跨世界累积）
- **目标**：让新档世界中出现"原来自己 / 同伴"的游荡英雄，达成"遇到原来的自己"的效果
- **范围**：
  - **仅玩家本体**（`Hero.MainHero`）
  - **仅玩家招募过且存活的 NPC**（`Clan.PlayerClan.Companions` 且 `IsAlive`）
  - 不复制家族全部成员 / 固定名 NPC 英雄
- **策略**：跨存档 `StringId` 不稳定，采用**重建相似游荡英雄**而非"找回原对象"
  - 导出：`HeroProfile`（姓名、来源、文化、等级、技能、特性、职业、性别、体型）
  - 复刻：`HeroCreator.CreateSpecialHero` 重建 → `SetName / SetNewOccupation / SetSkillValue / SetTraitLevel` 还原
  - 文化取自模板 `CharacterObject.Culture`（Hero 无 `Culture` 属性）
- **验证**：MCM 按钮«列出已复刻英雄（验证）»读取 `ResurrectedHeroTracker` 登记表

## 4. 排除功能（仍不继承的部分）

> 注：玩家人物的基础模板（姓名、文化、等级、技能、特性、职业、性别、体型）**已实现**跨世界复刻（v0.6.0）。以下为当前版本仍**不继承**的内容：

| 排除项 | 原因 |
|--------|------|
| 英雄完整状态（装备/部队/家族关系） | 仅复刻"游荡英雄模板"，不还原装备、部队、家族从属等完整状态 |
| 物品/装备/部队继承 | 超出政治格局继承范围 |
| 外交关系/战争状态 | 设计复杂度高，优先级低 |
| 玩家本体作为可控角色复用 | 玩家是新世界的独立存在；旧档玩家仅以"游荡英雄"形式出现，不可控 |

## 5. 非功能需求

| 需求 | 指标 |
|------|------|
| 兼容性 | 支持 Bannerlord v1.2.x |
| 依赖 | Newtonsoft.Json (已内嵌或依赖) |
| 性能 | 导入/导出在 100ms 内完成 |
| 可扩展 | 支持通过 `IGameAdapter` 接口适配未来版本 |
