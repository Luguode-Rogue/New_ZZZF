## 文档职责

### 现行主文档

`功能/*.md`、项目架构、开发规范和测试标准描述“现在应该怎么做”。它们是日常开发的首要阅读对象。

### 历史证据

Bug 修复记录、代码探索、工作日志、审计、阶段计划、旧教程和旧 Handoff 用来回答“当时为什么这么做”。它们不因为进入历史区就失去价值。

### Bug 经验必须完整保留

任何修复经验至少保留：

`问题现象 → 触发条件 → 日志/异常/堆栈 → 初始假设 → 关键排查步骤 → 失败方案 → 失败原因 → 最终根因 → 最终修复 → 验证结果 → 版本/API 前置条件 → 快速定位关键词`

失败方案必须保留，避免未来再次走已经证伪的路线。

`历史/BUG_HISTORY.md` 只是统一检索入口，不替代原始 Bug 文档。

## 冲突处理

不同文档存在冲突时，优先级见 `项目文档/DOCUMENT_STATUS.md`：当前代码与最近一次实机验证最高，其次是现行主文档，最后才是历史资料。

这不意味着删除旧文档。旧文档继续保留，用于恢复完整排错上下文与设计历史。
