## 文档整理原则

### 1. 主文档描述“现在应该怎么做”

功能、架构、开发规范和测试标准进入现行文档。历史文档不再与现行规范混在一起。

### 2. 原始记录不删除

本次整理不删除历史 Bug、排错、代码探索和工作日志中的有效信息。需要压缩重复信息时，只建立新的统一入口，不以摘要替换原始记录。

### 3. Bug 经验必须完整保留

任何修复经验至少保留：问题现象、触发条件、日志/异常/堆栈、初始假设、每个关键排查步骤、失败方案及失败原因、最终根因、最终修复方案、验证结果、版本/API 前置条件以及未来再次遇到时的快速定位关键词。

因此 `历史/BUG_HISTORY.md` 是**索引与检索入口**，不是删减原始记录的替代品。

## 旧目录说明

现有 `项目文档`、`UI开发文档`、`技能系统`、`技术参考`、`Bug修复记录`、`工作日志` 等目录中的原始 Markdown 保留，用于完整历史追溯。新的主文档负责统一入口与当前结论。
