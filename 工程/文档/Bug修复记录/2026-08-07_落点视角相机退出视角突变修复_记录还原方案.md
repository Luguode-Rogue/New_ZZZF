# 落点视角相机：退出视角突变修复（记录还原方案）

- 日期：2026-08-07
- 模块：ProjectileTrajectorySystem / Systems/SiegeLandingCameraSystem.cs
- 状态：**已解决（游戏内验证：进/出前后视角一致，切换后晃动鼠标不再突变）**

## 功能背景

为攻城武器（投石车/投石器）新增"落点视角"模式：玩家操作工程器时按切换键，相机从玩家视角
平滑飞到弹道落点正上方俯视（含绕 Z 轴 180° 旋转、滚轮调高度、落点标记跟随）。再次按键或
脱离工程器时退出，相机交还引擎。

## 失败原因（迭代过程）

### 失败 1：退出视角方向被改变，强行"飞回进入前位置"
- 实现：退出时走 `FlyingBack` 状态，动画把相机从落点飞回进入前记录的位置，结束时再
  `UpdateFreeCamera(_originalFrame)` 交还引擎。
- 结果：第一次退出视角异常；以异常视角再次进入并退出才正常。
- 根因：引擎在 `CustomCamera = null` 之后的当帧会用其内部逻辑接管 CombatCamera 并覆盖帧，
  `UpdateFreeCamera` 的二次处理与引擎接管互相打架，导致视角跳变/突变。

### 失败 2：HoldingExit 状态（飞回后保持自定义相机，等鼠标移动再交还）
- 实现：飞回完成后不直接 Release，进入 `HoldingExit` 保持 `CustomCamera` 不置空，靠
  `AllowInputWithCustomCamera = true` 自由看；鼠标一动立即 Release 交还引擎。
- 结果：① 无法再次进入新模式（HoldingExit 状态挡住 Toggle）；② 即便切换正常，切换后
  晃动鼠标仍会触发视角突变。
- 根因：把"交还"和"自由操控"混在一起，鼠标事件触发 Release 的瞬间引擎再次覆盖帧，
  突变本质未消除；且 HoldingExit 作为非 Idle 状态拦截了下一次 Toggle。

### 失败的共性结论
只要"退出"依赖一段动画或对相机帧的二次改写，就会与引擎接管当帧的帧覆盖冲突，产生突变。
问题的关键不是"飞回哪里"，而是 **退出这一刻如何把控制权交还给引擎**。

## 成功原因（最终方案）

采用用户指定的极简原则：**进入时记录视角，退出时只还原记录的视角，不动其他任何东西。**

1. 进入时（`Toggle` → `StartFlyingOut` 之前）抓取并保存玩家当前视角：
   `_originalFrame = _ms.CombatCamera.Frame; _hasSavedPlayerFrame = true;`
   进入后的俯视/旋转/滚轮逻辑完全由本系统自定义，与原引擎视角解耦。

2. 退出时（`Toggle` 的退出分支 / 自动退出 / 异常退出）一律直接调用 `Release()`，
   **不再飞回、不再 `UpdateFreeCamera`、不再任何动画**：
   - 先把记录视角原样写回引擎相机：`_ms.CombatCamera.Frame = _originalFrame;`
   - 紧接着置空 `CustomCamera` 交还控制权：`_ms.CustomCamera = null; _ms.AllowInputWithCustomCamera = false;`
   - 移除 `FlyingBack` 状态与 `StartFlyingBack`，状态机简化为 `Idle / FlyingOut / Holding`。

3. 因为交还前 CombatCamera 已是进入前记录的视角，引擎接管当帧看到的就是同一个视角，
   没有偏差，所以"进/出前后视角完全一致"，且切换后晃动鼠标不再突变（退出瞬间已交还，
   不存在悬而未决的自定义相机状态）。

## 关键代码位置

- `SiegeLandingCameraSystem.cs`
  - `Toggle()`：进入前保存 `_originalFrame`；退出分支直接 `Release()`。
  - `Release()`：还原 `_originalFrame` 到 `CombatCamera.Frame` → 置空 `CustomCamera`。
  - `CameraState`：`Idle / FlyingOut / Holding`（已删除 `FlyingBack`）。

## 日志验证点
- `[Cam] ENTER saved frame: ...` —— 进入时记录的视角矩阵。
- `[Cam] RESTORE frame: ...` —— 退出时还原的视角矩阵（应与 ENTER 一致）。

## 经验沉淀
- Bannerlord 中 `MissionScreen.CustomCamera` 接管相机后，交还（设为 null）的当帧引擎会
  用内部逻辑覆盖 CombatCamera 帧。任何在交还前后的帧改写/动画都可能与该覆盖冲突。
- 最稳的"还原视角"做法：交还 **之前** 把 CombatCamera 帧直接赋值为进入前记录值，再置空
  CustomCamera。不要依赖 `UpdateFreeCamera` 或飞回动画做还原。
- 进入新模式与"退出后的常规视角"应解耦：进入后不依赖原引擎，退出只还原记录的视角，二者
  互不牵连，可各自独立迭代。
