# TacticalMap HTMLUI 重制设计

> 状态：开发中
> 
> 目标分支：`feature/tacticalmap-htmlui-redesign`
> 
> 本文是 TacticalMap 子项目的功能与交互设计基线。后续实现、测试和验收均以本文为准；若代码与本文冲突，应先更新设计文档，再修改实现。

## 1. 功能定位

TacticalMap 是战场辅助型战术地图，不负责替代 Bannerlord 的完整战斗控制。其核心职责有三项：

1. 提供固定朝向的战场态势图。
2. 在需要时提供地图鼠标操作。
3. 通过地图直接向当前选择的编队发布移动、朝向和镜头切换指令。

HTMLUI 负责界面表现、输入焦点和鼠标交互；TacticalMap Core 负责地形、世界坐标、单位追踪、编队数据、订单和战场镜头。

## 2. Bannerlord 战场输入约束

Bannerlord 战场默认不提供自由鼠标。玩家通常通过游戏本身的鼠标唤起机制进入鼠标状态，因此 TacticalMap 不能假定“地图显示 = 鼠标已经存在”。

因此地图必须把“地图显示”和“地图操作”分成两个独立状态：

- **显示状态**：地图可见，但不占用鼠标，玩家继续正常战斗。
- **操作状态**：地图可见，并由 HtmlUI 捕获鼠标，玩家可以点击地图。

HtmlUI 使用 `Passive` 和 `Captured` 两种输入模式切换这两个状态，不在 TacticalMap 内重新实现 WebView2 输入系统。

## 3. N 键状态机

N 键是 TacticalMap 的唯一主入口，分为短按和长按两种操作。

### 3.1 默认状态

战斗开始后 TacticalMap 默认处于：

- 地图：显示
- 布局：小地图
- 鼠标：隐藏
- 输入：游戏控制
- 操作：关闭

这是最常用状态，不影响正常战斗。

### 3.2 N 短按

短按只切换“是否操作地图”，不改变地图显隐和大小。

| 当前状态 | N 短按后 |
|---|---|
| 小地图 / 不操作 | 小地图 / 操作 |
| 小地图 / 操作 | 小地图 / 不操作 |
| 全屏 / 不操作 | 全屏 / 操作 |
| 全屏 / 操作 | 全屏 / 不操作 |

进入操作状态后：

- 鼠标显示。
- HtmlUI 切换到 `Captured`。
- 地图可以接受鼠标输入。

退出操作状态后：

- 鼠标交互结束。
- HtmlUI 切换到 `Passive`。
- 游戏重新获得输入。

### 3.3 N 长按

长按负责地图显隐与全屏切换：

```text
小地图 → 全屏地图 → 隐藏 → 小地图
```

长按从小地图进入全屏时保留当前操作状态：

- 小地图 / 不操作 → 全屏 / 不操作
- 小地图 / 操作 → 全屏 / 操作

从全屏长按后直接隐藏地图；隐藏后下一次长按重新回到默认的小地图 / 不操作状态。

长按阈值由 `TacticalSettings.ToggleLongPressThreshold` 控制，默认 0.45 秒。按下和松开之间只记录时间，不在按住过程中重复切换状态。

### 3.4 ESC

ESC 只退出地图操作，不关闭地图：

- 小地图 / 操作 → 小地图 / 不操作
- 全屏 / 操作 → 全屏 / 不操作

## 4. 地图布局

### 4.1 小地图

小地图用于战斗过程中的快速观察：

- 位于屏幕角落。
- 不遮挡主要战斗画面。
- 不提供复杂控制面板。
- 默认只展示必要的战场信息。

### 4.2 全屏地图

全屏地图用于需要集中观察和操作战场时的情况。

布局分为：

- 左侧：编队列表。
- 中央：战术地图。
- 右侧：当前选中编队信息。
- 底部：状态与操作提示。

全屏不是简单放大小地图，而是提供更高的信息密度和更明确的战场管理区域。

## 5. 地图空间规则

### 5.1 固定北方

地图始终保持固定北方朝向，北方位于地图上方。

玩家自身方向通过方向线表示，不旋转整张地图。

### 5.2 不提供的功能

当前版本明确不实现以下功能：

- 地图缩放。
- 地图拖动。
- 自动居中。
- 自动跟随玩家。
- 地图边缘单位方向箭头。
- Density Heatmap。
- 命令预览。
- Attack Move。
- 战争迷雾或敌情隐藏。

地图比例和空间范围保持稳定，使玩家容易建立战场空间记忆。

## 6. 三键地图交互

进入地图操作状态后，不设置“移动模式 / 面向模式 / 镜头模式”三个互相切换的命令按钮。鼠标三个键拥有固定职责：

### 左键：移动命令

在地图上点击位置后，当前选中的编队向该位置移动。

### 中键：镜头切换

在地图上点击位置后，将战场镜头切换到该世界位置。

该操作不向部队发布移动或朝向命令。

### 右键：朝向命令

在地图上点击位置后，当前选中的编队以该位置为朝向目标。

右键不改变编队移动目的地。

## 7. 编队选择

全屏地图提供编队列表。选中编队后：

- 地图上的对应编队高亮。
- 其他编队适当降低视觉优先级。
- 右侧显示该编队详细信息。
- 后续左键移动和右键朝向命令作用于当前选择。

允许通过 Ctrl + 点击进行多编队选择；该功能用于后续完善群体命令，核心订单接口不需要重新设计。

## 8. 单位显示层级

地图不通过缩放改变单位层级，而是根据**玩家与单位的世界距离**自动选择显示方式。

### 近距离

玩家附近达到阈值范围的单位显示为单独 Agent 点位。

表现目标：

- 看清局部战场。
- 能看到单个士兵的分布。
- 友军、敌军、中立单位使用不同颜色。

### 远距离

距离超过阈值后，不继续绘制单个 Agent，而显示对应的编队信息。

表现目标：

- 降低远距离区域的信息噪声。
- 用编队位置、人数和朝向表达战场结构。

默认 Agent 详细距离由 `TacticalSettings.AgentDetailDistance` 控制，初始值为 90 米。该值是表现参数，不改变核心追踪逻辑。

## 9. 地图信息

### 9.1 地形

默认显示地形基础图层。

### 9.2 风险层

默认开启，主要表达：

- 悬崖。
- 水域。
- 森林/植被相关危险或阻碍区域。

风险层必须保持低透明度，不能覆盖基础地图导致地图难以阅读。

### 9.3 Player

玩家使用明显的圆形标记，并额外显示玩家当前朝向。

### 9.4 Formation

编队使用方形标记。颜色与形状共同表达阵营，避免完全依赖颜色。

建议约定：

| 对象 | 颜色 | 形状 |
|---|---|---|
| 玩家 | 青/蓝 | 圆形 | 
| 友军 | 绿色 | 方形 |
| 敌军 | 红色 | 菱形或红色方形边框 |
| 中立 | 灰色 | 中性几何图形 |

### 9.5 Camera Target

当前战场镜头位置使用菱形标记表示。

## 10. 已执行命令线

地图采用“结果反馈”而不是“目标预览”。

鼠标移动到地图上时不显示虚假命令线；只有玩家真正点击以后，才记录最近执行的命令线。

- 移动：实线。
- 朝向：虚线或方向线。
- 镜头：不产生部队命令线，只更新 Camera Target。

命令线属于视觉反馈，不应成为新的订单系统。

## 11. 情报原则

TacticalMap 不模拟战争迷雾，也不主动隐藏 C# 已获得的战场信息。

能够从战场系统读取的信息可以直接显示，包括：

- 敌我阵营。
- 编队位置。
- 编队人数。
- Agent 位置。
- 朝向。
- 镜头目标。

该设计是本 Mod 的战术辅助定位，不模拟原版信息限制。

## 12. 输入与生命周期

### Passive

地图显示但不操作时使用 `HtmlUiInputMode.Passive`：

- WebView 不抢鼠标。
- Bannerlord 正常接收战斗输入。

### Captured

地图操作时使用 `HtmlUiInputMode.Captured`：

- WebView 获取鼠标焦点。
- 地图点击命令正常执行。
- ESC 或 N 短按可以退出操作状态。

### Mission End

任务结束时必须：

1. 隐藏 TacticalMap。
2. 恢复 Passive 输入。
3. 清除 UI 状态。
4. 销毁 Tactical Camera 资源。
5. 防止上一场战斗的 UI 状态泄漏到下一场战斗。

## 13. 性能原则

静态地形数据只在地图烘焙完成后发布；动态数据按 TacticalMap 的刷新周期发布，而不是每帧重新构造完整地图。

动态数据重点包括：

- Player 位置与朝向。
- Camera Target。
- Formation 快照。
- Agent 快照版本。

HTML 端只重绘 Canvas 的动态层，不重复创建静态地图资源。

## 14. C# / HTML 职责边界

### C# Core

负责：

- Terrain Bake。
- World ↔ UV 转换。
- FormationTracker。
- AgentTracker。
- OrderSystem。
- CameraController。
- Mission 生命周期。

### C# HtmlUI Consumer

负责：

- HtmlUi 页面注册。
- ContentRoot。
- UI 状态机同步。
- `Passive/Captured` 输入模式。
- HTML Command / State 桥接。

### HTML

负责：

- Canvas 地图绘制。
- 编队/Agent 显示。
- 小地图与全屏布局。
- 选择和视觉高亮。
- 命令线反馈。
- 鼠标事件转换为 Command。

HTML 不直接修改 Bannerlord 世界对象，也不重新实现订单或镜头逻辑。

## 15. 当前实现状态

已完成：

- N 短按 / 长按状态机。
- 小地图 / 全屏 / 隐藏三种布局状态。
- 地图操作 / 非操作两种输入状态。
- Passive / Captured 输入切换。
- 左键移动。
- 中键镜头切换。
- 右键朝向。
- 地形和风险图层。
- Player / Formation / Camera 标记。
- Agent / Formation 距离分级显示的数据链。
- 全屏编队列表与选中详情的 HTML 原型。
- Mission End 清理逻辑。

待实机验证：

- N 长按阈值在战场输入环境中的体感是否合适。
- Passive ↔ Captured 切换后鼠标是否稳定出现/隐藏。
- 中键镜头切换与 Bannerlord 原生鼠标输入是否冲突。
- 90 米 Agent 详细显示阈值是否合适。
- 大规模战斗中的 Agent 快照传输和 Canvas 重绘性能。
- 全屏地图在不同分辨率和 UI 缩放下的布局。

## 16. 验收标准

一次完整战斗中，默认进入后应看到小地图且鼠标仍不可见；N 短按后鼠标出现并可操作地图；再次短按或 ESC 后鼠标退出且地图仍然显示；N 长按后进入全屏，再次长按隐藏，再次长按回到默认小地图。

在操作状态下：

- 左键必须只执行移动命令。
- 中键必须只切换战场镜头。
- 右键必须只执行朝向命令。
- 不存在 Attack Move。
- 不存在地图缩放、拖动和自动居中。
- 近距离必须显示单个 Agent，远距离必须自动回退为编队显示。
- 地图信息必须保持完整，不启用战争迷雾。

以上规则构成 TacticalMap HTMLUI 重制版的第一版交互基线。
