# New_ZZZF 开发指南

## 开发原则

先确认功能主文档，再确认当前代码状态，最后修改实现。不要直接依据历史审计或旧教程判断现行 API。

## 新功能流程

1. 在对应功能主文档定义目标、边界和完成标准。
2. 确认现有模块与生命周期入口。
3. 将版本敏感代码隔离到兼容层。
4. 实现并进行最小化验证。
5. 完成异常、重复初始化和 Mission 结束清理测试。
6. 修复问题时完整记录排查链路、失败方案和根因。
7. 更新功能主文档与 Bug 经验库。

## UI 开发

表现层只负责显示和输入；数据、状态和游戏逻辑留在运行时层。HtmlUI 与 Gauntlet 共存时必须明确所有权，防止焦点、输入和生命周期互相覆盖。

## 调试

默认不开启逐帧高频日志。需要排查时，应记录可复现条件、关键状态转移和异常堆栈，而不是简单增加大量日志。
