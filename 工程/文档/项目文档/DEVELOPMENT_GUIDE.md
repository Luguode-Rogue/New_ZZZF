# New_ZZZF 开发指南

## 开发前

1. 先阅读 `工程/文档/README.md`。
2. 找到对应 `功能/*.md` 主文档。
3. 涉及 Bannerlord API / UI / MCM 时先查 `技术参考/`。
4. 修改已经有历史排错经验的代码前，先查 `历史/BUG_HISTORY.md`。

## 开发中

- 保持功能逻辑、UI、配置和兼容层职责分离。
- 不要为了修一个版本问题，把版本判断散落到大量业务代码。
- 不要用高频日志作为默认调试手段。
- 对每个生命周期入口考虑重复初始化、重复关闭、场景切换和异常中断。

## Bug 修复

Bug 修复不是“改到不报错”为止。必须记录：

- 触发条件
- 原始错误信息
- 排查链路
- 已证伪的假设
- 失败方案与失败原因
- 根因
- 最终修改
- 验证场景

这样才能真正减少下一次排错时间。

## 文档更新

功能行为变化 -> 更新 `功能/*.md`。  
可复用技术结论 -> 更新 `技术参考/`。  
完整排错过程 -> 更新 `Bug修复记录/` 或 `工作日志/`，并加入 `历史/BUG_HISTORY.md` 索引。

## 历史文档

不要直接覆盖历史文档来“修正文档”。当前结论与历史事实应分开，避免以后无法判断旧方案为什么被淘汰。
