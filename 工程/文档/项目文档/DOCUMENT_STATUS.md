# New_ZZZF 文档与状态事实源

## 事实优先级

当不同文档之间出现冲突时，按以下顺序判断：

1. 当前分支实际代码与配置。
2. 最近一次已完成的实机验证记录。
3. `工程/文档/功能/*.md` 等现行主文档。
4. 项目架构、开发、测试规范。
5. 日期工作日志、阶段性计划、审计、旧 Handoff。

历史文档不得因为旧状态而被删除；它们用于追溯当时为什么采用某种方案。

## 维护规则

### 新功能

先更新对应功能主文档，再补充历史记录或计划。

### 新 Bug

先完整记录原始排错，再把快速定位信息加入 `历史/BUG_HISTORY.md`。

### API 兼容问题

必须记录具体 Bannerlord 版本、异常类型、受影响 API、失败方案、替代 API 和验证版本。

### 当前结论变更

不得覆盖掉旧结论。应在主文档更新现行状态，并让历史记录保留原方案与失效原因。
