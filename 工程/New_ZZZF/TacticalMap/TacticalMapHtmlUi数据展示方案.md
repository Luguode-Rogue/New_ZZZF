# TacticalMap HtmlUI 数据展示方案

## 1. 目标

TacticalMap HtmlUI 只负责战术地图的视觉呈现与用户输入；地图数据的采集、计算、坐标转换、订单执行和镜头控制全部留在 C#。

遵循 BannerlordHtmlUI Framework 的 State / Command / Request 模型：

- **State**：持续变化、用于绘制的信息。
- **Request**：初始化时需要读取的静态地图数据。
- **Command**：用户在地图上执行的动作。
- HTML/JS 不直接访问 Bannerlord API，不创建 WebView2。

## 2. 必须显示的数据

### 2.1 地图底图

- 战场地形图。
- 风险/威胁图层。
- 地图实际世界范围与 UV 坐标转换所需的元数据。
- 地图是否已经完成烘焙。

### 2.2 玩家

- 玩家当前位置。
- 玩家朝向。
- 玩家标记必须和普通部队、敌我编队区分。

### 2.3 编队

每个编队至少显示：

- 友军/敌军属性。
- 编队名称。
- 当前人数。
- 编队平均位置。
- 编队朝向。

远距离时以编队为主要信息单位。

### 2.4 Agent

近距离时允许显示完整 Agent：

- UV 位置。
- 我方/敌方。
- 中立。

显示粒度必须遵循距离 LOD：

- 靠近镜头目标：显示 Agent。
- 远离镜头目标：隐藏 Agent 细节，改为编队表示。

距离阈值由 C# 设置提供，HTML 只负责应用 LOD。

### 2.5 镜头目标

- 当前战场镜头目标位置。
- 与玩家标记、编队标记保持不同视觉层级。

### 2.6 UI 状态

- 当前模式：隐藏 / 小地图被动 / 小地图交互 / 全屏被动 / 全屏交互。
- 当前是否捕获输入。
- 地图数据是否准备完成。

## 3. 用户交互对应的数据动作

| 鼠标 | C# Command | 行为 |
|---|---|---|
| 左键 | `mapClick` / `move` | 地图位置转换为移动命令 |
| 中键 | `cameraClick` | 切换战场镜头目标 |
| 右键 | `mapClick` / `face` | 向地图位置下达朝向命令 |
| ESC | `exitInteraction` | 退出 HTML 交互，恢复被动模式 |

禁止 HTML 直接执行游戏逻辑；Command 只传递地图 UV 和动作类型。

## 4. 数据刷新策略

### 静态数据

地图烘焙完成后，通过一次 `getMapData` Request 获取：

- terrain RGBA
- risk RGBA
- 输出尺寸
- world 原点
- world 宽高

避免把大块静态纹理每个 Tick 都通过 State 广播。

### 动态数据

通过 State `map` 更新：

- 玩家
- 镜头目标
- 编队
- Agent
- UI 状态
- Agent 详细显示距离
- Agent 数据版本

动态更新采用节流，不与地形烘焙绑定。

## 5. HTML 视觉结构

```text
┌─────────────────────────────────────────┐
│ 状态 / 图层 / 交互提示                  │
│                                         │
│          ┌───────────────────┐          │
│          │                   │          │
│          │    战术地图       │          │
│          │                   │          │
│          └───────────────────┘          │
│                                         │
│ 图例                         编队信息    │
└─────────────────────────────────────────┘
```

小地图模式尽量只保留地图、关键标记和最少状态信息；全屏模式再显示完整的编队信息和图层控制。

## 6. Framework 约束

1. Consumer 不创建 WebView2。
2. 页面只通过 `HtmlUiConsumerScope` 注册 ContentRoot/Page/State/Command/Request。
3. Page reload/navigation 后 JS Runtime 可以重建，不能依赖旧 JS 对象永久存在。
4. 所有 listener、timer、request 都必须在 `pagehide`/dispose 后停止。
5. State 只发布可序列化业务数据，不发布 Bannerlord 对象。
6. 静态大数据优先通过 Request 获取，避免高频 State 广播。

## 7. 数据扩展预留

后续可以在不改变基础协议的情况下继续增加：

- 选中编队。
- 当前订单/订单目标。
- 攻击范围或危险范围。
- 视野/侦测范围。
- 地形语义图层开关。
- 更多编队细节面板。
- 战斗阶段、时间和其他战场态势信息。

这些数据必须先进入 TacticalMap C# 数据模型，再通过 State/Request 提供给 HTML。
