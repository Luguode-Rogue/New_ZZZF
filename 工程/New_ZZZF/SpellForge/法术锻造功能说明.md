# 法术锻造（SpellForge）—— Noita 式组合法术系统

## 一、功能概述

在 Bannerlord 模块 **New_ZZZF** 的“新技能界面”中，新增一个 **“法术锻造”** 入口按钮。
玩家点击后打开独立的锻造界面，可以从官方组件库中点击组装法术模块（投射物 / 修正器 / 触发器），
实时预览解释结果，点击 **“确认创建”** 即动态生成一个真正的 `SkillBase` 法术，
自动装入当前英雄的法术槽并持久化存档。进入战斗后，该自创法术与手写法术（如火球术）走**完全相同的施法链路**
（选中法术槽 + 右键施放 + 扣法力 + 冷却）。

本质：把“技能”拆成可组合的数据组件，用解释器在运行时合成行为（Noita 法杖编程思想）。

---

## 二、打开方式（按你的要求改为界面按钮）

- 入口：**新技能界面（CustomSkillScreen）** 右上角“法术锻造”按钮 → `ExecuteOpenSpellForge()`
- 通过 `ScreenManager.PushScreen(new SpellForgeScreen(...))` 叠加打开
- 关闭：界面内“关闭 (Esc)”按钮或 Esc 热键，关闭后自动同步新技能界面状态
- **不再使用全局热键**（原 F8 方案已废弃）

## 四、数据流（新系统兼容旧系统，以旧系统为准）

核心原则：**法术锻造新系统不另造一套法术体系，而是复用旧 ZZZF 的 `SkillFactory` / `SkillBase` / `SkillCatalog` / `HeroSkillData`**。
新系统制作出的「自建法术」（`CompositeSpell`）注册进旧 `SkillFactory._skillRegistry` 后，
**会和旧系统的预设法术（火球术、辉剑圆阵、雷击术…）一起出现在「全部魔法」列表里，供玩家选择（装备/编辑）**。

```
【左栏：可配置组件】
玩家在左侧点选法术
   ↓  AddNode(id)
SpellForgeVM._build 追加一个旧 SkillBase 实例（来自 SkillFactory.Create(id)）
   ↓
中栏「当前组装」实时显示已选旧法术序列

【确认创建自建法术】
玩家点「确认创建」并填写法术名称
   ↓  ConfirmSpell()
new CompositeSpell("Comp_xxxx", name, _build)
   ↓  注册进旧系统（关键）
SkillFactory.RegisterSkill("Comp_xxxx", composite)   ← 写入 SkillFactory._skillRegistry
   ↓  重新拉取全部法术（含新注册的 Comp_xxxx）
RefreshAllSpells() → SkillCatalog.LoadFromFactory().GetSkillsOfType(Spell)
   ↓
新自建法术与旧系统法术混排进「全部魔法」右栏（不自动装备，等玩家选）

【玩家选择装备】
玩家在右栏点「装备」
   ↓  EquipSpell(id)
SkillFactory.Create(id) → 旧 SkillBase
   ↓  写入旧英雄配置
_heroSkillData.Spells[空槽] = SkillUIData.FromSkillBase(baseSkill)
   ↓  回调
_onCommit(id) → CustomSkillScreenVM 刷新技能界面

【持久化 & 战斗】
SaveCurrentHeroSkills() → SkillSet 存档（英雄法术栏持久化，旧逻辑不变）
   ↓  进战斗
AgentSkillComponent.SpellSlots[i] 加载 → 右键施放 → CompositeSpell.Activate()
   ↓  以旧系统为准
CompositeSpell.Activate 内部依次调用每个子 SkillBase.Activate（火球/辉剑圆阵等旧施法链路）
```

要点：
- 新系统只负责「组合 + 注册」，所有法术的创建/装备/存档/施放**全部走旧系统接口**，不引入独立运行时。
- 自建法术 `CompositeSpell` 是 `SkillBase` 的子类（`Skills/CompositeSpell.cs`），`Activate` 时按装配顺序触发各子法术，
  因此与手写旧法术（如火球术）走**完全相同的施法链路**（选中槽 + 右键 + 扣法力 + 冷却）。
- 编辑：右栏点「编辑」→ 把 `CompositeSpell.Components` 拆解回中栏组装区，可继续修改后重新确认。

## 七、性能与实现方案（已采用）

### 7.1 复用集中式弹道驱动（最高性能）
`CompositeSpell` **不额外开任何循环**。施放时仅做两件事：
1. `Activate` 中创建 `GameEntity` 并挂子弹网格，登记进 `SkillSystemBehavior.WoW_CustomGameEntity` + `WoW_ProjectileDB`；
2. 飞行推进由 `SkillSystemBehavior` 的集中式计时器统一驱动（每 0.01s 推进位置/追踪转向，每 0.5s 刷新追踪目标），
   与 `JianQi`/`LingHunDanMu`/`HuiJianYuanZhen` 等手写法术**完全相同的底层路径**。

### 7.2 命中结算（O(1)，不遍历全场）
系统在每帧推进后回调 `CompositeSpell.GameEntityDamage(entity)`：
- 用 `Scene.RayCastForClosestEntityOrTerrain` 做 **O(1) 地形碰撞**（命中地形/障碍即销毁，避免穿地）；
- 用 `Script.FindAgentsWithinSpellRange(pos, radius)` 做**小半径命中兜底**（精确且无需遍历全场景）；
- 命中后调用 `ApplyHit` 结算：`CalculateFinalMagicDamage` 伤害 + 元素状态（Burning/Freeze/Weaken/Heal）+ 触发器（explode AOE / chain 连锁 / pierce 穿透）。

### 7.3 状态系统（真实生效）
| 状态 | 效果 |
|------|------|
| `BurningState` | 持续火焰伤害（每秒 DOT） |
| `FreezeState` | **真实减速**：`OnApply` 降低 `agent.AgentDrivenProperties.MaxSpeedMultiplier`，`OnRemove` 恢复（缓存原倍率，带 try/catch 容错） |
| `WeakenState` | 持续毒素伤害（DOT） |
| `HealState` | 持续回血（HOT） |

## 八、发散评估：功能是否完整？是否可用？

### 8.1 已可用的部分（核心闭环完整成立）
1. **入口正确**：从新技能界面按钮打开，符合你的要求，与现有技能系统融合自然。
2. **数据驱动**：组件与法术都是纯数据，解释器逻辑与“写死技能”彻底解耦。
3. **施法路径一致**：`CompositeSpell` 是真正的 `SkillBase`，装入 `SpellSlots` 后右键施放，
   法力消耗、冷却、公共 CD 全部复用原生 `AgentSkillComponent` 机制——**自创与手写逻辑一致**。
4. **真实飞行弹道**：已接入 `WoW_ProjectileDB` 集中驱动 + `GameEntityDamage` 命中结算，
   **玩家能看到子弹飞出去并在命中时结算**（含地形碰撞消除、追踪制导、扇形散射）。
5. **持久化**：通过 `CustomSkillScreenVM.SaveCurrentHeroSkills()` 落盘，重开游戏仍在。
6. **元素/状态完整**：fire 燃烧、freeze 减速、poison 中毒、heal 治疗，全部真实生效。
7. **基础法术库齐全**：15 个常见法术（攻击/控制/治疗/连锁/爆炸）预设，全部经由解释器实现，
   体现“系统本身即可生成常见法术”。

### 8.2 仍可继续打磨（增强方向，非阻塞）
1. **触发器递归生成子弹**：当前 `trigger_explode/chain` 是“命中后追加效果”，
   Noita 还能“死亡触发/计时触发/生成新子弹”，可后续扩展子节点递归。
2. **组合合法性校验（Tags）**：玩家仍可拼出“无效组合”（界面已提示需至少一个投射物），
   可加类型系统限制（如追踪不能作用于地面技能）。
3. **法术管理**：自创法术当前可创建/装备/二次编辑，但缺“删除/重命名/列表管理”UI。
4. **视觉细节**：子弹网格复用了通用 `power_*` 网格，可按元素换色（已通过 `BaseColor` 拖尾区分）；
   音效/专属粒子可后续补。
5. **法力消耗公式**：`ResourceCost` 目前按子弹数估算，可随 modifier 精细联动。

### 8.3 结论
- **功能完整、已可玩**：作为“可组合法术引擎”已从 MVP 升级为具备真实飞行弹道、元素状态、丰富基础法术库的可用系统，
  且完全接入 New_ZZZF 原生技能体系，自创法术与手写法术表现一致。
- **下一步建议**：① 触发器递归子节点（死亡/计时触发）→ ② 法术管理 UI（删除/重命名）→ ③ 元素反应扩展（油/水/雷链）→ ④ 专属粒子/音效。

- `SkillBase.Activate(Agent) : bool`、`SkillBase.IsValid => true` —— 基类约定，子类按签名实现。
- `Agent.AgentDrivenProperties.MaxSpeedMultiplier` —— 移动速度倍率覆盖（可读写）。
- `Scene.RayCastForClosestEntityOrTerrain(...)`、`Script.FindAgentsWithinSpellRange(...)`、`Script.GetTargetedInRange(...)`、`Script.FindClosestAgentToCaster(...)` —— 既有命中/索敌辅助。

- `AgentBuff` / `StateContainer.AddState(...)` —— 状态系统挂载（模块统一 API，非 `BuffContainer`）。
- `DamageType` 枚举：火=`FIRE_DAMAGE`、冰=`ICE_DAMAGE`、电=`ELECTRICITY_DAMAGE`、毒=`TOXIN_DAMAGE`。

### 10.4 ⚠️ UI（XML）实际加载位置（关键，曾因此反复修不对）

- **游戏运行时加载的 XML 在模块根目录**：`Modules\New_ZZZF\GUI\Prefabs\`（注意：`Modules\New_ZZZF\` 是模块根，不是 `工程\New_ZZZF\`）。
- `工程\New_ZZZF\GUI\Prefabs\` 与 `工程\New_ZZZF\_Module\Prefabs\`（后者为空）**均不参与运行时加载**。`csproj` 引用 `_Module\Prefabs\`（空目录），`Bannerlord.BuildResources` 不会复制任何 Prefab，因此模块根 `GUI\Prefabs\` 的 XML 是"野生"手工维护的，直接改模块根那份才生效。
- **务必修改 `Modules\New_ZZZF\GUI\Prefabs\` 下的 XML**：
  - `CustomSkillScreen.xml`：入口按钮「法术锻造」（左上角，`ExecuteOpenSpellForge`）。
  - `SpellForgeScreen.xml`：法术锻造主界面（若模块根缺失此文件，界面加载会失败 → 表现为异常/空白/泛黄）。
- `工程\New_ZZZF\GUI\Prefabs\SpellForgeScreen.xml` 是死副本（不被加载），不要改它。
